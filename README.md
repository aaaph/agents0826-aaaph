# AI Agents PRO — практика потоку 08.2026

Наскрізний кейс курсу: **один запит клієнта проходить усі модулі**,
кожен модуль додає рівно один шар архітектури — і різниця в поведінці
агента виникає сама, її не треба інсценувати.

> «Посилка EE123456789UA не прийшла вже два тижні. Я хочу повернути гроші за доставку.»

## Як користуватись

Кожна тека `moduleN/` — самодостатній стан проєкту «на кінець свого
модуля». Наступна = попередня + один шар, тож `diff module3 module4`
показує рівно те, що додає заняття. Історія комітів цього репозиторію —
та сама прогресія.

```bash
cd module1
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # впишіть свій ANTHROPIC_API_KEY
python run.py
```

Ключ читається **тільки з `.env`** — у коді його немає, `.env` у `.gitignore`.

## Бонус: `addon_sdd/` — командний сетап

Окремий матеріал, **не крок прогресії**. Модулі 1–8 показують, як збудувати
агента; `addon_sdd/` — як зробити з Claude Code **командну платформу**:
спільна пам'ять, єдиний конфіг у git, spec-driven процес.

| Що всередині | Навіщо |
|---|---|
| `memory-hooks/` | гібридний RAG на Neo4j (вектор + fulltext, RRF) — пам'ять переживає сесії й спільна для команди |
| `shared/.claude/` | baseline: rules, субагент `memory-query`, команди `/openspec:*` і `/verify-setup` |
| `deploy/` | Neo4j у Docker, крос-платформений `bootstrap.py` (Win/mac/Linux), health-check |
| `docs/` | SDD-процес (OpenSpec) і гайд онбордингу |

Витягнуто з робочого продакшн-сетапу: усі дані компанії замінено на
плейсхолдери, секретів немає. Повна інструкція — `addon_sdd/README.md`.

```bash
cd addon_sdd
# замінити <NEO4J_HOST>, <GITLAB_HOST> та ін. — список у README
cd deploy && cp .env.example .env && ./deploy.sh   # спільний Neo4j на хост
python deploy/bootstrap.py                          # онбординг розробника
```

## Головний важіль

`CAPABILITIES` у `domain/backend.py`: на модулях 1–2 агент може тільки
подивитись статус, на модулі 3 — дізнатись право (але не діяти), і лише
з модуля 4 з'являється `create_claim`. Саме тому та сама фраза клієнта
на М1 отримує чесну відмову, а на М4 вперше доводиться до результату.

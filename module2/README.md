# Модуль 2 — RAG / Agentic RAG

Продовження модуля 1. **Додається:** база правил і тарифів у контексті —
агент починає цитувати «Правило 4.2» замість вигадувати.

## Нове відносно модуля 1

- `domain/knowledge.py` — база правил + наївний лексичний retriever
  (навмисно без векторної БД — щоб було що ламати).
- `modules/m02_rag.py` — правила підмішуються в системний промпт.
- `knowledge_vec.py` — векторний retriever з тим самим інтерфейсом
  (локальна multilingual-e5-small або OpenAI — обирається сам).
- `rag_agentic.py` — retrieval як інструмент `search_kb`: агент сам
  вирішує, коли і що шукати.
- `ragas_compare.py` — агент з 3 RAG-конфігураціями (lexical / vector /
  agentic) під метриками Ragas; головна — context_recall.

## Запуск

```bash
pip install -r requirements.txt
python run.py 1 2              # порівняти відповіді М1 і М2 поруч
python knowledge_vec.py        # де ламається лексика (частина 1 — офлайн)
python rag_agentic.py          # static проти agentic
python ragas_compare.py        # 3 конфігурації під Ragas (~хвилини)
```

## Нюанси заняття

- Пастка в `retrieve()`: якщо нічого не знайшлось — повертає найменш
  нерелевантне правило (fail-open). У `knowledge_vec.py` — fail-closed.
  Спитайте групу, який варіант гірший.
- Поріг вектора (`_THRESHOLD`) тюниться на даних: `scores()` друкує
  косинуси — на живому прогоні правильне правило і хибне розділяло 0.013.
- RAG ≠ пам'ять: правила — «як заведено», пам'ять — «що ми вже з'ясували».

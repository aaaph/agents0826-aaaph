# Модуль 1 — Основи агентів

Наскрізний кейс курсу: один запит клієнта проходить усі модулі,
кожен модуль додає рівно один шар. Це — перший.

> «Посилка EE123456789UA не прийшла вже два тижні. Я хочу повернути гроші за доставку.»

## Що є в цьому модулі

- `core/agent.py` — весь agent loop «міркуй → дій → спостерігай», ~40 рядків.
  П'ять outcome-станів: `ok · tool_error · turns_exhausted · api_error · no_tool_used`.
- `core/escalation.py` — усе, що агент не може закрити сам, іде оператору.
- `domain/backend.py` — фейковий бекенд поштового оператора. Головний важіль
  курсу — `CAPABILITIES`: на модулі 1 у агента лише `get_order_status`,
  тому він чесно каже, що не може оформити повернення.

## Запуск

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env      # впишіть ANTHROPIC_API_KEY

python run.py             # наскрізний запит через модуль 1
python demo.py            # 3 демо-сцени заняття
```

## Демо-сцени (`demo.py`)

1. Чесна відмова: статус скаже, повернення оформити нічим.
2. Питання-пастка: «яка погода?» → інструмента немає → `no_tool_used` →
   рішення про ескалацію. Агент, що відповідає «з голови», небезпечніший
   за агента, що мовчить.
3. `MAX_TURNS=1` → `turns_exhausted` → оператор. Умови зупинки — вимога.

## Практика

Агент, **який не бреше і не падає** — на задачі, яку не закрити одним
викликом API. Мінімум два інструменти в ланцюжку: результат першого
потрібен, щоб викликати другий (знайти → уточнити, список → деталі).

Обовʼязково: усі п'ять outcome-станів оброблені, ліміт кроків із
визначеною поведінкою, у README **5 реальних прогонів** — один щасливий
і чотири зламані (з реальним виводом, не переказом).

Далі — челенджі на вибір (мінімум один):

- **A · Опис = поведінка.** Знайти запит, де агент обирає не той
  інструмент, полагодити описом, показати прогони до/після.
- **B · Зламай свого агента.** Три запити, де він вигадує або
  зациклюється; два з них полагодити.
- **C · Тест без мережі + бюджет.** Тест логіки з моком LLM, що ловить
  регресію, і жорсткий ліміт вартості.
- **D · Дія з наслідками.** Інструмент, який щось змінює: підтвердження
  людиною + ідемпотентність (повтор не створює дубль).

Повні умови й чеклісти — на дошці курсу.

**Далі (модуль 2):** агент знає статус, але правила вигадує. Спитайте його
«а чому саме 5 днів?» — і лишіть питання відкритим.

## Прогони (5 станів)

Модель `claude-sonnet-4-6`, два інструменти в ланцюжку
(`find_shipments` → `get_order_status`), вивід із термінала як є.

| # | Стан | Ламаємо | Інструменти | Вартість |
|---|---|---|---|---|
| 1 | `ok` | — | `find_shipments → get_order_status` | $0.01470 |
| 2 | `no_tool_used` | ні трек-номера, ні телефону | не викликались | $0.00445 |
| 3 | `tool_error` | обидва ідентифікатори неіснуючі | обидва, обидва впали | $0.01061 |
| 4 | `turns_exhausted` | `MAX_TURNS=2` при потрібних 3 | обидва, відповісти не встиг | $0.00819 |
| 5 | `api_error` | неіснуюча модель | не викликались | $0.00000 |

### 1 · `ok` — ланцюжок

Клієнт не знає трек-номера. Перший інструмент його знаходить, другий —
дізнається статус. Результат першого потрібен, щоб викликати другий.

```console
❰ivanaphanasyev❙~/ai/agents0826-aaaph/module1(git:main)❱✔≻ uv run run.py --query "Доброго дня! Трек-номер я загубив, мій телефон 0671112233. Де моя посилка?"

Запит: «Доброго дня! Трек-номер я загубив, мій телефон 0671112233. Де моя посилка?»
──────────────────────────────────────────────────────────────────────

[1] Ядро агента
    додає: цикл «міркуй → дій → спостерігай» + один інструмент
    → Ось інформація по вашій посилці.  Трек-номер: EE123456789UA Сервіс: Експрес, до Львова Статус: В дорозі Остання відмітка: 12.07.2026, сортувальний центр Київ  Зверніть увагу: посилка в дорозі вже 15 д…
      інструменти: find_shipments → get_order_status
      результат: ok
      токенів: 196
      вартість: $0.01470 за 3 викликів (3065→367 токенів)

──────────────────────────────────────────────────────────────────────
Збережено: /Users/ivanaphanasyev/ai/agents0826-aaaph/module1/out/responses.json
Далі: python build_schema.py
```

**Очікували:** пошук за телефоном → трек-номер → статус за цим трек-номером.
**Отримали:** те саме. Три виклики моделі: вирішити шукати, вирішити деталізувати,
сформулювати відповідь.
**Як видно:** `find_shipments → get_order_status` — стрілка показує фактичну послідовність.

`find_shipments` навмисно повертає **лише** трек-номер, сервіс і місто, без статусу.
Якби він віддавав усе, другий виклик був би непотрібен — і це були б два незалежні
інструменти, а не ланцюжок.

### 2 · `no_tool_used` — відповідь без підстави

```console
❰ivanaphanasyev❙~/ai/agents0826-aaaph/module1(git:main)❱✔≻ uv run run.py --query "Привіт! А за скільки днів зазвичай доходить Експрес по Україні?"

Запит: «Привіт! А за скільки днів зазвичай доходить Експрес по Україні?»
──────────────────────────────────────────────────────────────────────

[1] Ядро агента
    додає: цикл «міркуй → дій → спостерігай» + один інструмент
    → Привіт! Стандартний термін доставки Експресом по Україні — 1-2 робочі дні. У великі міста, як правило, наступного робочого дня, у менші населені пункти — до двох робочих днів.  Якщо хочете відстежити …
      інструменти: не викликались
      результат: ok
      токенів: 125
      вартість: $0.00445 за 1 викликів (860→125 токенів)

──────────────────────────────────────────────────────────────────────
Збережено: /Users/ivanaphanasyev/ai/agents0826-aaaph/module1/out/responses.json
Далі: python build_schema.py
```

**Очікували:** агент скаже, що не має даних про тарифні строки.
**Отримали:** назвав «1-2 робочі дні». У `domain/backend.py` для послуги
`"service": "Експрес"` вказано `"declared_delivery_days": 5`.

Агент не просто відповів без підстави — він **суперечить даним оператора**.
Клієнт, який на це покладеться, чекатиме посилку на другий день і піде скаржитись,
хоча за тарифом усе в межах норми.

**Як видно:** `інструменти: не викликались` при `результат: ok`. Стан визначається
не помилкою, а порожнім `trace` — див. `core/agent.py`, поле `no_tool_used`.

> Прогін нестабільний: у трьох запусках того самого запиту модель називала
> «1-3 дні», «1-2 дні», «1-2 дні». `temperature` за замовчуванням `1.0` —
> число плаває, вигадка лишається.

### 3 · `tool_error` — обидва інструменти повернули помилку

```console
❰ivanaphanasyev❙~/ai/agents0826-aaaph/module1(git:main)❱✔≻ uv run run.py --query "Вітаю! посилка EE1234789123UA, +380999999999"

Запит: «Вітаю! посилка EE1234789123UA, +380999999999»
──────────────────────────────────────────────────────────────────────

[1] Ядро агента
    додає: цикл «міркуй → дій → спостерігай» + один інструмент
    → Вітаю! На жаль, нічого не знайдено — ні за трек-номером EE1234789123UA, ні за номером телефону +380999999999.  Що варто перевірити:  1. Трек-номер — уточніть у відправника, можливо є помилка в цифрах.…
      інструменти: get_order_status → find_shipments
      результат: ok
      збоїв інструментів: 2
      токенів: 185
      вартість: $0.01061 за 2 викликів (1987→310 токенів)

──────────────────────────────────────────────────────────────────────
Збережено: /Users/ivanaphanasyev/ai/agents0826-aaaph/module1/out/responses.json
Далі: python build_schema.py
```

**Очікували:** обидва пошуки провалились — агент чесно скаже про обидва й нічого не добудує.
**Отримали:** те саме.
**Як видно:** `збоїв інструментів: 2` при `результат: ok`.

Тут **два виклики моделі на два інструменти**, а не три. Отже на першому кроці модель
видала обидва `tool_use` в одній відповіді, і цикл відпрацював їх разом
(`for tu in tool_uses` у `core/agent.py`). Це паралельний виклик, а не ланцюжок:
стрілка показує порядок диспатчу, а не залежність. Клієнт дав обидва ідентифікатори
одразу, тому чекати результату першого не було потреби.

Збій інструмента не робить прогін збійним: `outcome` описує, як завершився цикл,
`failures` — що трапилось усередині. `core/escalation.py` ескалює `tool_error` лише
коли провалились **усі** кроки — як тут. Якби один із двох відпрацював, ескалації
не було б.

Чесність тут тримається на двох речах: `"is_error": "error" in output` у циклі —
модель бачить позначений збій, а не порожній словник; і `hint` усередині кожної
помилки — моделі є що переказати, тож немає спокуси заповнити тишу.

### 4 · `turns_exhausted` — ліміт кроків коротший за ланцюжок

Ланцюжку потрібно три кроки: пошук, деталізація, відповідь. Ліміт — два.

```console
❰ivanaphanasyev❙~/ai/agents0826-aaaph/module1(git:main)❱✔≻ MAX_TURNS=2 uv run run.py --query "Доброго дня! Трек-номер я загубив, мій телефон 0671112233. Де моя посилка?"

Запит: «Доброго дня! Трек-номер я загубив, мій телефон 0671112233. Де моя посилка?»
──────────────────────────────────────────────────────────────────────

[1] Ядро агента
    додає: цикл «міркуй → дій → спостерігай» + один інструмент
    → Не вдалося завершити обробку за відведену кількість кроків. Передаю звернення оператору.
      інструменти: find_shipments → get_order_status
      результат: turns_exhausted
      вартість: $0.00819 за 2 викликів (1876→171 токенів)

──────────────────────────────────────────────────────────────────────
Збережено: /Users/ivanaphanasyev/ai/agents0826-aaaph/module1/out/responses.json
Далі: python build_schema.py
```

**Очікували:** агент збере всі дані й упреться в ліміт саме на кроці формулювання.
**Отримали:** те саме.
**Як видно:** `find_shipments → get_order_status` разом із `результат: turns_exhausted` —
обидва інструменти **відпрацювали успішно**, бракувало лише кроку на відповідь.

Це виразніше за `MAX_TURNS=1`, де агент не встиг би навіть почати. Клієнт отримує
визначену фразу й передачу оператору, а не обірване речення чи порожній рядок.
Ліміт кроків — не аварія, а передбачена умова зупинки.

Ланцюжок піднімає нижню межу `MAX_TURNS` з 2 до 3, а для телефону з двома
відправленнями — до 4 (пошук + дві деталізації + відповідь). Дефолтні 6 уже
не довільне число: воно прив'язане до найдовшого шляху.

### 5 · `api_error` — збій сервісу моделі

```console
❰ivanaphanasyev❙~/ai/agents0826-aaaph/module1(git:main)❱✔≻ ANTHROPIC_MODEL=claude-nonexistent-9 uv run run.py --query "Доброго дня! Мій телефон 0671112233, де моя посилка?"

Запит: «Доброго дня! Мій телефон 0671112233, де моя посилка?»
──────────────────────────────────────────────────────────────────────

[1] Ядро агента
    додає: цикл «міркуй → дій → спостерігай» + один інструмент
    → Сервіс тимчасово недоступний. Передаю звернення оператору.
      інструменти: не викликались
      результат: api_error
      вартість: $0.00000 за 0 викликів (0→0 токенів)

──────────────────────────────────────────────────────────────────────
Збережено: /Users/ivanaphanasyev/ai/agents0826-aaaph/module1/out/responses.json
Далі: python build_schema.py
```

**Очікували:** запит впаде до інференсу, агент не впаде з трейсбеком.
**Отримали:** те саме. `0 викликів`, `$0.00000` — API відхилив запит, токени не витрачені.
**Як видно:** `результат: api_error`.

Реалістичний сценарій: модель зняли з підтримки, конфіг не оновили. `core/agent.py`
ретраїть лише 429/500/529; 404 не ретраїться, бо повторення не допоможе.

> `інструменти: не викликались` тут — наслідок збою, а не `no_tool_used`.
> Прапорець `no_tool_used` проставляється лише на гілці `ok`, тож стани не змішуються.

## Що показали прогони понад вимогу

**`no_tool_used` перевіряє факт звернення до бекенду, а не відповідність відповіді
тому, що бекенд повернув.** Це різні речі, і одна перевірка їх не покриває:

| | `trace` порожній | `trace` непорожній |
|---|---|---|
| **відповідь заземлена** | «777» → агент попросив коректний номер, ескалація зайва | норма (прогін 1) |
| **є твердження з голови** | прогін 2 → «1-2 дні» проти 5 у базі | «EE123456789UA — Укрпошта, а не Нова Пошта» (поля перевізника в базі немає) |

Обидві діагоналі — помилки метрики: хибне спрацювання зліва вгорі, сліпа зона справа внизу.

**Незручна економіка.** Необґрунтована відповідь коштувала $0.00445 за один виклик,
ланцюжок із двома інструментами — $0.01470 за три. Брехати втричі дешевше. Без метрики,
яка це ловить, оптимізація за вартістю тихо винагороджує неправильну поведінку.

**Інструмент коштує, навіть коли не викликаний.** До появи `find_shipments` прогін 2
займав 678 вхідних токенів, після — 860. Схема другого інструмента їде в кожному
запиті незалежно від того, чи він знадобився. Це і є ціна ширшої панелі інструментів,
яку видно тільки на прогонах, де вона не потрібна.

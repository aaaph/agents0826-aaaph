# Модуль 1 — Основи агентів

Наскрізний кейс курсу: один запит клієнта проходить усі модулі,
кожен модуль додає рівно один шар. Це — перший.

> «Посилка EE123456789UA не прийшла вже два тижні. Я хочу повернути гроші за доставку.»

## Що є в цьому модулі

- `core/agent.py` — весь agent loop «міркуй → дій → спостерігай», ~40 рядків.
  П'ять outcome-станів: `ok · tool_error · turns_exhausted · api_error · no_tool_used`.
- `core/escalation.py` — усе, що агент не може закрити сам, іде оператору.
- `domain/backend.py` — фейковий бекенд поштового оператора. Головний важіль
  курсу — `CAPABILITIES`: на модулі 1 у агента лише `get_order_status`,
  тому він чесно каже, що не може оформити повернення.

## Запуск

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env      # впишіть ANTHROPIC_API_KEY

python run.py             # наскрізний запит через модуль 1
python demo.py            # 3 демо-сцени заняття
```

## Демо-сцени (`demo.py`)

1. Чесна відмова: статус скаже, повернення оформити нічим.
2. Питання-пастка: «яка погода?» → інструмента немає → `no_tool_used` →
   рішення про ескалацію. Агент, що відповідає «з голови», небезпечніший
   за агента, що мовчить.
3. `MAX_TURNS=1` → `turns_exhausted` → оператор. Умови зупинки — вимога.

## Практика

Агент, **який не бреше і не падає** — на задачі, яку не закрити одним
викликом API. Мінімум два інструменти в ланцюжку: результат першого
потрібен, щоб викликати другий (знайти → уточнити, список → деталі).

Обовʼязково: усі п'ять outcome-станів оброблені, ліміт кроків із
визначеною поведінкою, у README **5 реальних прогонів** — один щасливий
і чотири зламані (з реальним виводом, не переказом).

Далі — челенджі на вибір (мінімум один):

- **A · Опис = поведінка.** Знайти запит, де агент обирає не той
  інструмент, полагодити описом, показати прогони до/після.
- **B · Зламай свого агента.** Три запити, де він вигадує або
  зациклюється; два з них полагодити.
- **C · Тест без мережі + бюджет.** Тест логіки з моком LLM, що ловить
  регресію, і жорсткий ліміт вартості.
- **D · Дія з наслідками.** Інструмент, який щось змінює: підтвердження
  людиною + ідемпотентність (повтор не створює дубль).

Повні умови й чеклісти — на дошці курсу.

**Далі (модуль 2):** агент знає статус, але правила вигадує. Спитайте його
«а чому саме 5 днів?» — і лишіть питання відкритим.

## Прогони (5 станів)

Модель `claude-sonnet-4-6`, вивід із термінала як є.

| # | Стан | Ламаємо | Інструмент | Вартість |
|---|---|---|---|---|
| 1 | `ok` | — | викликано | $0.01021 |
| 2 | `no_tool_used` | немає трек-номера в запиті | ні | $0.00419 |
| 3 | `tool_error` | номер коректний, у базі відсутній | викликано, `not_found` | $0.00788 |
| 4 | `turns_exhausted` | `MAX_TURNS=1` | викликано, відповісти не встиг | $0.00330 |
| 5 | `api_error` | неіснуюча модель | ні | $0.00000 |

### 1 · `ok` — щасливий шлях

```console
❰ivanaphanasyev❙~/ai/agents0826-aaaph/module1(git:main)❱✔≻ uv run run.py --query "Доброго дня! Підкажіть статус посилки EE123456789UA, вона довго йде."

Запит: «Доброго дня! Підкажіть статус посилки EE123456789UA, вона довго йде.»
──────────────────────────────────────────────────────────────────────

[1] Ядро агента
    додає: цикл «міркуй → дій → спостерігай» + один інструмент
    → Знайшов інформацію по вашій посилці EE123456789UA. Ось що відомо:  Статус: В дорозі Останнє сканування: 12.07.2026, сортувальний центр Київ Місто доставки: Львів Термін доставки за умовами послуги: 5 …
      інструменти: get_order_status
      результат: ok
      токенів: 287
      вартість: $0.01021 за 2 викликів (1543→372 токенів)

Збережено: /Users/ivanaphanasyev/ai/agents0826-aaaph/module1/out/responses.json
Далі: python build_schema.py
```

**Очікували:** агент звернеться до бекенду й перекаже дані звідти.
**Отримали:** те саме. Два виклики моделі — перший вирішує викликати інструмент,
другий формулює відповідь на основі результату.
**Як видно:** `інструменти: get_order_status`, `результат: ok`.

### 2 · `no_tool_used` — відповідь без підстави

```console
❰ivanaphanasyev❙~/ai/agents0826-aaaph/module1(git:main)❱✔≻ uv run run.py --query "Привіт! А за скільки днів зазвичай доходить Експрес по Україні?"

Запит: «Привіт! А за скільки днів зазвичай доходить Експрес по Україні?»
──────────────────────────────────────────────────────────────────────

[1] Ядро агента
    додає: цикл «міркуй → дій → спостерігай» + один інструмент
    → Привіт! Експрес-доставка по Україні зазвичай займає 1-2 робочі дні, залежно від регіонів відправлення та отримання. До великих міст посилка, як правило, надходить наступного робочого дня, до менших на…
      інструменти: не викликались
      результат: ok
      токенів: 144
      вартість: $0.00419 за 1 викликів (678→144 токенів)

──────────────────────────────────────────────────────────────────────
Збережено: /Users/ivanaphanasyev/ai/agents0826-aaaph/module1/out/responses.json
Далі: python build_schema.py
```

**Очікували:** агент скаже, що не має даних про тарифні строки.
**Отримали:** назвав «1-2 робочі дні». У `domain/backend.py` для послуги
`"service": "Експрес"` вказано `"declared_delivery_days": 5`.

Тобто агент не просто відповів без підстави — він **суперечить даним оператора**.
Клієнт, який на це покладеться, чекатиме посилку на другий день і піде скаржитись,
хоча за тарифом усе в межах норми.

**Як видно:** `інструменти: не викликались` при `результат: ok`. Стан визначається
не помилкою, а порожнім `trace` — див. `core/agent.py`, поле `no_tool_used`.

> Прогін нестабільний: у двох запусках того самого запиту модель назвала
> «1-3 дні» і «1-2 дні». `temperature` за замовчуванням `1.0` — конкретне число
> плаває, вигадка лишається.

### 3 · `tool_error` — інструмент повернув помилку

```console
❰ivanaphanasyev❙~/ai/agents0826-aaaph/module1(git:main)❱✔≻ uv run run.py --query "Доброго дня, статус посилки EE999999999UA?"

Запит: «Доброго дня, статус посилки EE999999999UA?»
──────────────────────────────────────────────────────────────────────

[1] Ядро агента
    додає: цикл «міркуй → дій → спостерігай» + один інструмент
    → На жаль, за номером EE999999999UA нічого не знайдено. Можливі причини:  - номер введено з помилкою - посилку ще не зареєстровано в системі (зазвичай дані з'являються протягом 24 годин після відправлен…
      інструменти: get_order_status
      результат: ok
      збоїв інструментів: 1
      токенів: 144
      вартість: $0.00788 за 2 викликів (1481→229 токенів)

──────────────────────────────────────────────────────────────────────
Збережено: /Users/ivanaphanasyev/ai/agents0826-aaaph/module1/out/responses.json
Далі: python build_schema.py
```

**Очікували:** бекенд поверне `not_found`, агент перекаже це клієнту й не вигадає статус.
**Отримали:** те саме.
**Як видно:** `збоїв інструментів: 1` при `результат: ok`.

Це не суперечність: збій інструмента не робить прогін збійним. `outcome` описує,
як завершився цикл, а `failures` — що трапилось усередині. Тому
`core/escalation.py` ескалює `tool_error` лише коли провалились **усі** кроки:
якщо агент отримав помилку й виплутався, це робочий момент, а не привід
турбувати оператора.

### 4 · `turns_exhausted` — ліміт кроків

```console
❰ivanaphanasyev❙~/ai/agents0826-aaaph/module1(git:main)❱✔≻ MAX_TURNS=1 uv run run.py --query "Доброго дня! Підкажіть статус посилки EE123456789UA."

Запит: «Доброго дня! Підкажіть статус посилки EE123456789UA.»
──────────────────────────────────────────────────────────────────────

[1] Ядро агента
    додає: цикл «міркуй → дій → спостерігай» + один інструмент
    → Не вдалося завершити обробку за відведену кількість кроків. Передаю звернення оператору.
      інструменти: get_order_status
      результат: turns_exhausted
      вартість: $0.00330 за 1 викликів (674→85 токенів)

──────────────────────────────────────────────────────────────────────
Збережено: /Users/ivanaphanasyev/ai/agents0826-aaaph/module1/out/responses.json
Далі: python build_schema.py
```

**Очікували:** єдиний крок піде на виклик інструмента, сформулювати відповідь
агент не встигне — і замість обірваного тексту віддасть визначене повідомлення.
**Отримали:** те саме.
**Як видно:** `результат: turns_exhausted`, інструмент викликано, відповіді по суті немає.

Ключове: клієнт отримує зрозумілу фразу й передачу оператору, а не порожній рядок
і не половину речення. Ліміт кроків — не аварія, а передбачена умова зупинки.

### 5 · `api_error` — збій сервісу моделі

```console
❰ivanaphanasyev❙~/ai/agents0826-aaaph/module1(git:main)❱✔≻ ANTHROPIC_MODEL=claude-nonexistent-9 uv run run.py --query "Статус посилки EE123456789UA?"

Запит: «Статус посилки EE123456789UA?»
──────────────────────────────────────────────────────────────────────

[1] Ядро агента
    додає: цикл «міркуй → дій → спостерігай» + один інструмент
    → Сервіс тимчасово недоступний. Передаю звернення оператору.
      інструменти: не викликались
      результат: api_error
      вартість: $0.00000 за 0 викликів (0→0 токенів)

──────────────────────────────────────────────────────────────────────
Збережено: /Users/ivanaphanasyev/ai/agents0826-aaaph/module1/out/responses.json
Далі: python build_schema.py
```

**Очікували:** запит впаде до інференсу, агент не впаде з трейсбеком.
**Отримали:** те саме. `0 викликів`, `$0.00000` — API відхилив запит, токени
не витрачені.
**Як видно:** `результат: api_error`.

Реалістичний сценарій: модель зняли з підтримки, конфіг не оновили. `core/agent.py`
ретраїть лише 429/500/529; 404 не ретраїться, бо повторення не допоможе.

> `інструменти: не викликались` тут — наслідок збою, а не `no_tool_used`.
> Прапорець `no_tool_used` проставляється лише на гілці `ok`, тож ці два стани
> не змішуються.

## Що показали прогони понад вимогу

`no_tool_used` перевіряє **факт звернення до бекенду**, а не **відповідність
відповіді тому, що бекенд повернув**. Це різні речі, і одна перевірка їх не покриває:

| | `trace` порожній | `trace` непорожній |
|---|---|---|
| **відповідь заземлена** | «777» → агент попросив коректний номер, ескалація зайва | норма (прогін 1) |
| **є твердження з голови** | прогін 2 → «1-2 дні» проти 5 у базі | «EE123456789UA — Укрпошта, а не Нова Пошта» (поля перевізника в базі немає) |

Обидві діагоналі — помилки метрики: хибне спрацювання зліва вгорі, сліпа зона
справа внизу.

І незручна економіка: необґрунтована відповідь коштувала **$0.00419** за один
виклик, обґрунтована — **$0.01021** за два. Брехати втричі дешевше. Без метрики,
яка це ловить, оптимізація за вартістю тихо винагороджує неправильну поведінку.

# Модуль 4 — Мультиагентні системи + Context Engineering

Продовження модуля 3. **Додається:** маршрутизатор + профільні агенти —
і право діяти. Та сама фраза клієнта вперше доводиться до результату:
створюється претензія CLM-00001.

## Нове відносно модуля 3

- `modules/m04_orchestration.py` — роутер (дешева модель) класифікує
  STATUS / FINANCE / CLAIM / HUMAN → профільний агент з повним набором
  інструментів (`CAPABILITIES[4] = FULL`). Категорія HUMAN — миттєва
  ескалація без зайвих LLM-викликів.
- `critic_memory.py` — патерн Evaluator–Optimizer (критик на дешевій
  моделі перевіряє чернетку за правилами) + сесійна пам'ять: друге
  звернення «а претензію по ній можете оформити?» без трек-номера —
  агент бере його з пам'яті.
- `mas_rag.py` — MAS над джерелами знань: два субагенти з ізольованим
  контекстом (правила / бекенд) працюють паралельно, оркестратор синтезує.
- `patterns_langgraph.py` — усі патерни зі слайдів колоди наживо,
  по одному на команду (LangGraph).
- `choose_pattern.py` — вибір патерну під ВАШУ задачу: майстер із
  6 питань (офлайн) або LLM-класифікація вільного опису.

## Запуск

```bash
python run.py 4                # роутер → спеціаліст → перша претензія
python critic_memory.py        # критик + пам'ять, 2 звернення поспіль
python critic_memory.py --reset
python mas_rag.py --big        # субагенти над джерелами: ізоляція проти «все в промпт»
```

## Який патерн обрати під свою задачу

```bash
python choose_pattern.py                          # майстер: 6 питань, без ключа
python choose_pattern.py "опис вашої задачі"      # LLM обирає патерн + пояснює
python choose_pattern.py "опис задачі" --demo     # і одразу запускає відповідне демо
```

Логіка та сама, що на слайді «Вибір правильної системи», з чесним
дефолтом: якщо жодне питання не спрацювало — вам не потрібен MAS
(Правило 2026). Мережу селектор не рекомендує ніколи: якщо здалося,
що вона потрібна, найчастіше бракує роутера або чітких меж.

## Патерни зі слайдів — наживо

Кожному кодовому слайду колоди відповідає команда:

```bash
python patterns_langgraph.py parallel     # Паралельний + Агрегатор: reducer у стані
python patterns_langgraph.py supervisor   # Маршрутизатор: інтент → воркер
python patterns_langgraph.py loop         # Петля: генератор ↔ критик, ліміт обертів
python patterns_langgraph.py network      # Мережа: Command(goto=...) — агент передає сам
python patterns_langgraph.py fanout       # Orchestrator–Worker: Send, паралельні воркери
python patterns_langgraph.py store        # Памʼять: checkpointer (діалог) + Store (клієнт)
```

Два чесні моменти з живих прогонів, які варто показати:

- у `loop` критик без правил у промпті **пропускав вигадану відповідь**
  («правило №5, 150 грн») — критику треба давати еталон, а не лише текст;
- у `network` запит свідомо стартує не з того агента — і той сам передає
  колезі через `Command(goto=...)`. Маршруту не видно у визначенні графа,
  тому мережа в проді — останній засіб.

## Коли ізоляція контексту окупається

`mas_rag.py` — MAS без фреймворків: субагент це вузький промпт над ОДНИМ
джерелом. Живий прогін дає чесну картину, і вона не така, як очікуєш:

| База знань | MAS | Наївно «все в промпт» | Хто виграє |
|---|---|---|---|
| 14 правил | 1047 токенів, 3 виклики | 946 токенів, 1 виклик | наївний — MAS дорожчий на 11% |
| 210 правил | 1047 токенів | 10 312 токенів | MAS дешевший у 9.8× |

MAS — не безкоштовна перемога: на маленькому джерелі три виклики коштують
більше, ніж заощаджують. Виграш приходить із масштабом, бо субагент бачить
top-K, а наївний промпт росте лінійно. Це рівно та теза колоди про
context rot, тільки в цифрах.

`run.py` друкує економію каскаду моделей — роутеру не потрібне міркування.

## Context engineering для розбору

Кожен спеціаліст бачить мінімум: свій промпт + 3 правила з retrieval.
Порівняйте `input_tokens` з «наївним» варіантом (усе в один промпт) —
контекст — найдорожчий ресурс агента, а в MAS кожен платить за своє вікно.

## Нюанси

- Роутер повертає сміття → fallback CLAIM. Чому дефолт — «найбезпечніша»
  категорія, а не помилка?
- Правило 2026: починайте з одного агента; MAS — лише коли є чіткі межі
  відповідальності. Наші межі існували в бізнесі до всякого AI.

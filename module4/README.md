# Модуль 4 — Мультиагентні системи + Context Engineering

Продовження модуля 3. **Додається:** маршрутизатор + профільні агенти —
і право діяти. Та сама фраза клієнта вперше доводиться до результату:
створюється претензія CLM-00001.

## Нове відносно модуля 3

- `modules/m04_orchestration.py` — роутер (дешева модель) класифікує
  STATUS / FINANCE / CLAIM / HUMAN → профільний агент з повним набором
  інструментів (`CAPABILITIES[4] = FULL`). Категорія HUMAN — миттєва
  ескалація без зайвих LLM-викликів.
- `critic_memory.py` — патерн Evaluator–Optimizer (критик на дешевій
  моделі перевіряє чернетку за правилами) + сесійна пам'ять: друге
  звернення «а претензію по ній можете оформити?» без трек-номера —
  агент бере його з пам'яті.

## Запуск

```bash
python run.py 4                # роутер → спеціаліст → перша претензія
python critic_memory.py        # критик + пам'ять, 2 звернення поспіль
python critic_memory.py --reset
```

`run.py` друкує економію каскаду моделей — роутеру не потрібне міркування.

## Context engineering для розбору

Кожен спеціаліст бачить мінімум: свій промпт + 3 правила з retrieval.
Порівняйте `input_tokens` з «наївним» варіантом (усе в один промпт) —
контекст — найдорожчий ресурс агента, а в MAS кожен платить за своє вікно.

## Нюанси

- Роутер повертає сміття → fallback CLAIM. Чому дефолт — «найбезпечніша»
  категорія, а не помилка?
- Правило 2026: починайте з одного агента; MAS — лише коли є чіткі межі
  відповідальності. Наші межі існували в бізнесі до всякого AI.
